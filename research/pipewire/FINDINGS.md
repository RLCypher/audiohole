# Findings

Publication note: [CURRENT_BASELINE.md](CURRENT_BASELINE.md) records the newer remote `work` revision and supersedes historical AudioHole status/policy statements below. PipeWire source findings retain their pinned upstream baseline.

This investigation supports evaluating a small delay-feedback controller and a stateful adaptive resampler for AudioHole. It does not select a backend or authorize implementation.

| Finding | Evidence and qualification | AudioHole consequence |
|---|---|---|
| Equal nominal rates can still require active resampling | **Verified:** `setup_matching()` starts from follower status, suppresses matching only for equal clock names, and `need_resample()` includes `matching` independently of nominal rate equality. [S02](SOURCE_REFERENCES.md#s02) | Preserve the existing independent-clock requirement; a 48 kHz → 48 kHz route cannot automatically bypass drift compensation. |
| The examined PCM path uses a three-state DLL | **Verified:** `spa_dll_update()` has two cascaded first-order smoothing states plus an accumulating state; ALSA `update_time()` calls it. [S01](SOURCE_REFERENCES.md#s01), [S02](SOURCE_REFERENCES.md#s02) | A small controller is plausible; there is no evidence here that a general PID or Kalman estimator is required. |
| Main error is signed buffered delay relative to target | **Verified:** playback `delay-target`, capture `target-delay`; an IRQ-driven driver can instead use wake-up timing error converted to frames. Optional hardware timestamps normalize available-frame observations. [S02](SOURCE_REFERENCES.md#s02) | Queue occupancy is useful even without perfect clock telemetry. Normalize measurement phase before interpreting packet jitter as drift. |
| Correction has explicit direction and rate contracts | **Verified:** ALSA publishes `corr` for playback and `1/corr` for capture. A shared `spa_io_rate_match` connects hardware and converter. Converter reports required input/output size and filter delay. [S02–S05](SOURCE_REFERENCES.md#s02) | Define ratio units, direction, consumed/produced frame counts, and buffered filter history in the backend contract. Test the correction sign. |
| Slow tracking and discontinuity recovery are separate | **Verified:** error limits mark resynchronization; capture can forward data, playback can rewind or insert silence; DLL state resets. Suspend recovery can block in `poll()`. [S02](SOURCE_REFERENCES.md#s02) | Adapt the reset/re-prime principle; reject blocking recovery in an AudioHole callback. Large glitches are not ordinary ppm drift. |
| ALSA bandwidth is adaptive in this release | **Verified:** starts at 0.128; every >3 s chooses `clamp((abs(avg)+sqrt(abs(var)))/1000, .001, .128)`. The helper's `SPA_DLL_BW_MIN=.016` is not this caller's lower limit. [S01–S02](SOURCE_REFERENCES.md#s01) | Do not import constants or assume one settling time. Test fixed bandwidth against the actual adaptive rule. |
| Native adaptive-rate precision is finite | **Verified:** nonunity rate becomes `uint32_t(nominal_input/rate)`; fractional phase is carried between blocks. **Inferred:** roughly 20.8 ppm actuator spacing at 48 kHz can yield a bounded limit cycle. [S06](SOURCE_REFERENCES.md#s06) | Validate very small drift and actuator quantization; do not promise sub-ppm correction just because the DLL uses `double`. |
| Algorithmic filter latency is separately reportable | **Verified:** native delay is `n_taps/2-1` input frames, with a fractional phase term. **Calculated:** default quality at equal 48 kHz builds 64 taps, giving base delay 31 frames ≈0.646 ms. [S05–S06](SOURCE_REFERENCES.md#s05) | Include filter and queue delay in latency accounting; this number is not total route latency. |
| Low latency does not require reproducing PipeWire's server graph | **Verified:** graph activation uses dependency counters and eventfd, and links negotiate reusable buffers. [S09–S12](SOURCE_REFERENCES.md#s09) **Inferred:** this infrastructure is excessive for AudioHole's small in-process routes. | Keep bounded buffers, ownership, and deadlines; evaluate a destination event loop with a queue per independent destination. |
| Windows has useful user-mode equivalents | **Verified:** WASAPI supplies correlated clock positions, capture timestamps, render padding, events, and constrained shared periods; MMCSS exposes multimedia thread registration. [W01–W08](SOURCE_REFERENCES.md#w01) | No custom driver is needed for the proposed controller. Windows event cadence and endpoint behavior still need measurement. |
| Windows rate adjustment is not a universal callback actuator | **Verified:** `IAudioClockAdjustment::SetSampleRate` requires shared mode and must not be called from a real-time processing thread. [W09](SOURCE_REFERENCES.md#w09) | Evaluate an application-owned ASRC first; compare OS adjustment separately with its thread/mode restrictions. |
| License review must be per component | **Verified:** DLL/native converter headers are MIT; top-level LICENSE explicitly identifies ALSA and JACK exceptions; ACP contains LGPL-2.1-or-later code. [S18](SOURCE_REFERENCES.md#s18) | Studying principles does not require taking PipeWire as a dependency. Any source adaptation needs separate approval and notice review. |

## Checks actually executed

The original assignment is preserved as the first 18,840 bytes of AGENTS.md, SHA-256 `22ff9505a242ffb8db3a4e66487c4f4fa228a0b3835e615434deeb8963186c51`. Reference snapshots are checked against Git blob hashes. The C harness compiled and ran with `-Wall -Wextra -Werror`, tested ring wrap and the DLL's first-step algebra, and executed nine synthetic scenarios. Full results and limitations are in [EXPERIMENTS.md](EXPERIMENTS.md).

At Q=128 and 48 kHz, fixed-bandwidth ideal +100 ppm tracking over six **simulated** hours had error range −2.8493 to +0.0748 frames; the final 60 seconds were effectively zero at printed precision. Quantized actuator models stayed bounded with small residual oscillation. Adaptive bandwidth produced slower settling after a sign-changing rate step. These results verify only the stated model and code execution, not real hardware stability or inaudibility.

## Unresolved decisions

1. The original baseline did not formally choose destination pacing. Current remote `work` now accepts destination pacing, bounded FIFOs, and adaptive synchronization; D-030/D-034/O-005 still leave backend, algorithms, tuning, and transfer policy open. See [current-baseline update](CURRENT_BASELINE.md).
2. Which occupancy/timestamp observation has the least jitter for each Windows shared/exclusive endpoint? Shared capture padding describes the next packet, not the whole backlog. [W04](SOURCE_REFERENCES.md#w04)
3. Does a fixed-bandwidth DLL, simple bounded PI queue controller, or timestamp feed-forward plus occupancy feedback best meet the measured latency budget? No comparative hardware evidence exists here.
4. What correction bounds, slew policy, stale-clock gates, re-prime targets, and dropout policy suit AudioHole? The examined DLL helper contains no universal correction clamp or anti-windup guarantee.
5. What audible modulation and alias rejection follow from native-rate quantization or an alternative ASRC? The harness does not process audio samples.
6. How should clock identity be established for a Windows device's duplex endpoints? Same nominal rate, friendly name, USB enclosure, or device label is insufficient evidence by itself.
7. How does each backend expose consumed/produced counts, exact errors, delay, stream generations, and callbacks? Native WASAPI, miniaudio, and hybrid remain open candidates; this report does not rank their measured performance.
