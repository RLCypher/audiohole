# Publication baseline update

The initial research compared PipeWire against the supplied AudioHole snapshot `a2aaf7a8ca2b14c3ca37b59cf6d8bc255124a984`. That snapshot contains 14 Markdown documents only. Before publication, the existing GitHub remote was checked and `work` resolved to **`766ed88f7d7786bfb90fb7a520da34a15de010d1`**. The research branch is based on that current remote revision, not on the older local checkout. Historical baseline statements in the other reports describe the original pinned snapshot; the updates here govern current applicability.

## Changes verified before publication

- The remote tree now contains CMake, developer/model/GUI/platform source, and tests. Its [README](https://github.com/RLCypher/audiohole/blob/766ed88f7d7786bfb90fb7a520da34a15de010d1/README.md#building) explicitly describes a foundation and simulated GUI: it does **not** yet route real audio, and Test Beep is silent. This is source/documentation inspection, not an executed test of those components.
- [Current architecture](https://github.com/RLCypher/audiohole/blob/766ed88f7d7786bfb90fb7a520da34a15de010d1/ARCHITECTURE.md#sample-transfer-synchronization-and-fidelity) now accepts destination pacing, bounded FIFOs, adaptive synchronization, compatible capture sharing, and independent bounded destination queues. Destination pacing is no longer merely a research proposal.
- [D-030/D-034 and O-005](https://github.com/RLCypher/audiohole/blob/766ed88f7d7786bfb90fb7a520da34a15de010d1/DECISIONS.md#provisional-synchronization-direction--d-034--o-005-remain-open) still leave backend, converter, final synchronization algorithms, bypass eligibility, thresholds, and policy commitments open. Native event-driven WASAPI leads the backend comparison, but is not a finalized production selection.
- The provisional comparison is one engine with independent directional preferences: unchanged transfer, application-managed adaptive resampling, and Windows-managed **shared-render** rate adjustment where supported. Automatic is the proposed prototype default; strict preservation and discrete corrections remain internal/experimental. Selected preference, actual processing, synchronization health, and endpoint mode are independent concepts.
- [Current synchronization guidance](https://github.com/RLCypher/audiohole/blob/766ed88f7d7786bfb90fb7a520da34a15de010d1/ARCHITECTURE.md#provisional-synchronization-strategies-within-one-engine) explicitly notes that SetSampleRate must not run on a real-time thread and calls for checking initialization flags/API combinations. The research's Windows actuator caveat therefore corroborates an existing current requirement; it is not a newly imposed policy.
- [Current AGENTS](https://github.com/RLCypher/audiohole/blob/766ed88f7d7786bfb90fb7a520da34a15de010d1/AGENTS.md) and [ENGINEERING.md](https://github.com/RLCypher/audiohole/blob/766ed88f7d7786bfb90fb7a520da34a15de010d1/ENGINEERING.md) were reviewed. Existing real-time safety, cancellation, readable ownership/thread contracts, and evidence requirements remain in force.

## Effect on recommendations

The detailed PipeWire DLL, resampler, numerical, recovery, and licensing findings are unchanged because their upstream commit is fixed. The destination-paced queue/ASRC discussion now evaluates techniques **within an accepted architectural direction**. It does not seek approval to replace that direction. Exact controller, resampler, rate bounds, worker layout, correction transitions, and recovery semantics still require comparative evidence.

The small Linux harness remains an isolated numerical experiment. Its scenario inputs, one-frame illustrative settling window, and model assertions are research settings, not proposed production quality thresholds or accepted Windows behavior. Windows hardware latency, audio quality, resource costs, and endpoint compatibility remain unverified. This publication does not modify, build, test, or endorse the current GUI/model implementation.

No root specifications or implementation files are changed. The newer remote work is retained intact as the publication parent, while this research adds only `research/pipewire/` files.
