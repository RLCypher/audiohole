AUDIOHOLE — NORM TUTORIAL DIALOGUE
Version 2.8 — Norm voice pass, focused guidance, and working greetings

PURPOSE
A guided, completely fictional sandbox exercise. This is the dialogue for the owner's original tutorial workflow, NOT a replacement curriculum. No real devices are scanned, no audio is routed, and no profile/device files are written. The only permitted persistent change is the tutorial-complete flag. All lines appear in the status/personality panel. Settings keeps Personality, Animation, and DFA fields visible but disabled (grayed out), with “(Disabled for tutorial)” appended to their section headers; Replay Tutorial becomes Skip Tutorial.

FORMAT AND EVENT CONTRACT
Each beat has an ID, approved expression, activation cue and displayed dialogue. The prefix `NORM:` in this authoring file is a SCRIPT DESIGNATOR ONLY: never render a speaker label, `Norm:`, `NORM:`, or similar prefix in the application's dialogue panel. Display only the dialogue text. Fallback expression: idle.

Every tutorial transition is triggered by a confirmed EVENT, not a dialogue-duration timer: a response-button click, specified GUI navigation/change/save, or a simulated operation's `completed` event. The two deliberate simulated operations have approximately 20-second Deep / Full scan and 8-second Start Routing durations. Their simulation controllers emit completion events after their respective progress sequences. The tutorial state machine subscribes to those events; it does not advance by waiting an arbitrary number of seconds, firing a generic dialogue timeout, or assuming a result. No other progression timers are allowed.

Each narration-only beat has TWO bespoke player-response buttons, vertically stacked directly at the avatar's feet in the status/personality panel, styled like dating-sim dialogue choices. They are distinct full-width options, not side-by-side buttons. Clicking one advances exactly once to the same next beat, selecting the COMPLETE next-beat dialogue variant that incorporates Norm's reaction. No intermediate comeback screen, reaction-only beat, 'Continue' button, or extra click. When the next state requires a GUI action, that action (not a response button) is the progression gate. Keep the existing welcome screen intact.

During Tutorial Mode, the personality/status window is dedicated to Norm's tutorial dialogue, tutorial choices and avatar: suppress ordinary status messages, routing notifications, diagnostics chatter and routine system commentary from that window. Such messages may continue to exist in their ordinary non-dialogue views/logs if needed but MUST NOT replace, append to, or interrupt the current tutorial dialogue. Tutorial-owned simulation progress is shown on the scan/routing UI; Norm's specified operation dialogue stays in place until the completion event.

Highlight the actual directed GUI controls with an AUDIOHOLE PINK rectangular frame, matching the personality/avatar frame's exact border style (color, thickness, corners and visual treatment). Highlights track the target control's geometry and disappear/reposition on step changes. Prefer no overlay that prevents clicking or hides labels. Buttons use the existing application button language but adopt the two vertically stacked dating-sim-choice presentation at the avatar's feet. Disabled tutorial Settings sections: Personality, Animation and DFA stay visible but gray, with `(Disabled for tutorial)` in each section header; Replay Tutorial is replaced by Skip Tutorial.

Clicking Norm is the ONLY tutorial dialogue overlay governed by a timeout: show the selected bespoke click reaction for approximately 6 seconds, then restore the exact previous dialogue, choice buttons, highlighted control and expression without changing tutorial progress. An explicit user action during the overlay should still be handled correctly; dismiss the overlay and resolve the action against the saved current step rather than losing progress. Subsequent clicks can replace the overlay or be subject to a click cooldown; the return interval restarts on a new displayed reaction. Do not use that six-second timer for tutorial progression.

VOICE
Norm is a competent, laid-back audio tech who finds the whole business faintly ridiculous. He's conversational, affectionate in his sarcasm, mildly foul-mouthed when it lands, and comfortable with a little innuendo. He is teaching by doing, not dictating an instruction manual. Jokes should be woven into his actual speech, never tacked onto generic documentation. He never mocks the user for being new, and he never implies pretend actions actually accessed hardware.
